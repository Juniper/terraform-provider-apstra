# apstra_datacenter_virtual_network_assignment (Resource)

This resource assigns a Virtual Network to a Leaf Switch and Access Switches within a *Datacenter* Blueprint.


## Example Usage

```terraform
# This resource binds a virtual network to a leaf switch, and configures the
# leaf switch address within that virtual network, in a datacenter
# blueprint.

resource "apstra_datacenter_virtual_network_assignment" "example" {
  blueprint_id       = "some-blueprint-id"
  virtual_network_id = "some-virtual-network-id"
  leaf_switch_id     = "some-leaf-switch-id"
  vlan = 100 # optional
  ipv4_mode          = "forced"       # Optional - One of: [enabled|disabled|forced]
  ipv4_address       = "192.0.2.2/24" # Optional - The anycast gateway address is usually at ".1"

  # Optional - in the case of MLAG or ESI leaf switches, these are access
  # switches attached to *either* leaf switch in the pair. Failure to list
  # desired access switches from both members of the pair will result in
  # state churn and incomplete configuration.
  access_switch_ids  = ["some-access-switch-id-1", "some-access-switch-id-2"]
}
```

## Schema

### Required

- `blueprint_id` (String) ID of the Blueprint in which this Virtual Network Assignment is being configured.
- `leaf_switch_id` (String) ID of the Leaf Switch to which the Virtual Network is being assigned.
- `virtual_network_id` (String) ID of the Virtual Network to be assigned to a Leaf Switch.

### Optional

- `access_switch_ids` (Set of String) IDs of Access Switch children of the Leaf Switch.
**Note**: Any Access Switch in a Redundancy Group (ESI-LAG) must be listed here along with its redundancy partner in order to avoid state churn.
**Note**: If the Leaf Switch is part of an MLAG or ESI LAG redundancy group, any Access Switches homed to *either* Leaf Switch must be listed here in order to avoid state churn.
- `ipv4_address` (String) An IPv4 address to configure for this Leaf Switch on this Virtual Network. Not compatible with `ipv4_mode = "disabled"`. Requires IPv4 to be enabled on the Virtual Network.
- `ipv4_mode` (String) When and how to render a unique IPv4 address for this Leaf Switch on this Virtual Network. One of: `disabled`, `enabled`, `forced`. Note that this attribute is being written into the *config* graph. Data in the *staging* graph may not agree depending on what other features have been configured in the Blueprint. For example, attaching a Connectivity Template which requires the Leaf Switch to peer via BGP with a Generic System may cause the *staging* graph to reflect `forced` when `enabled` was configured via this resource. Furthermore, features configured in the Blueprint (like attaching a Connecitivty Template) may constrain the values which may be configured via this attribute. Requires IPv4 connectivity to be enabled in the Virtual Network.
- `ipv6_address` (String) An IPv6 address to configure for this Leaf Switch on this Virtual Network. Not compatible with `ipv6_mode = "disabled"` or `ipv6_mode = "link_local"`. Requires IPv6 to be enabled on the Virtual Network.
- `ipv6_mode` (String) When and how to render a unique IPv6 address for this Leaf Switch on this Virtual Network. One of: `disabled`, `enabled`, `forced`, `link_local`. Note that this attribute is being written into the *config* graph. Data in the *staging* graph may not agree depending on what other features have been configured in the Blueprint. For example, attaching a Connectivity Template which requires the Leaf Switch to peer via BGP with a Generic System may cause the *staging* graph to reflect `forced` when `enabled` was configured via this resource. Furthermore, features configured in the Blueprint (like attaching a Connecitivty Template) may constrain the values which may be configured via this attribute. Requires IPv6 connectivity to be enabled in the Virtual Network.
- `vlan` (Number) VLAN to use when associating the Virtual Network with this Leaf Switch. Note that if the Leaf Switch is part of a redundant pair, using mismatched values for this attribute will lead to state churn.
